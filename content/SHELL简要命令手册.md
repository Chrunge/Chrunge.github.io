## 1. 文件查看与监控

此部分核心在于：**根据文件大小和实时性要求选择正确的工具。**

## 2. 文本处理三剑客与数据清洗 (核心能力)

运维的高阶能力体现在对数据流（Stream）的处理上。请重点掌握 `grep` (过滤)、`awk` (取列)、`sed` (修改)。

#### 2.1 过滤与查找 (Grep)

| 命令 | 功能 | 常用选项 | 核心场景与实战 |
| :--- | :--- | :--- | :--- |
| **grep** | 文本搜索 | `-i` : 忽略大小写<br>`-v` : **反选** (排除)<br>`-E` : 支持扩展正则 (如 `\|` 或)<br>`-C 5` : 显示关键词前后5行 | **排除干扰项查进程**<br>`ps -ef \| grep nginx \| grep -v grep`<br><br>**查报错上下文** (难点)<br>`grep -C 10 "OutOfMemory" app.log` <br>*(不仅看报错，还看报错前后的堆栈)* |

#### 2.2 统计与排序 (Sort & Uniq)

| 命令 | 功能 | 常用选项 | 核心场景与实战 |
| :--- | :--- | :--- | :--- |
| **sort** | 排序 | `-n` : 按数值排序<br>`-r` : 倒序<br>`-k` : 指定列 | **查占用CPU最高的进程**<br>`ps aux \| sort -k3nr \| head -n 5` |
| **uniq** | 去重 | `-c` : **统计**重复次数 | **统计报错数量** (必须搭配sort)<br>`cat access.log \| awk '{print $9}' \| sort \| uniq -c \| sort -nr` |
| **wc** | 统计数量 | `-l` : 统计行数 | **统计连接数**<br>`netstat -an \| grep ESTABLISHED \| wc -l` |

#### 2.3 提取与替换 (Awk & Sed - 难点突破)

> **⚠️ 说明**：`cut` 虽然简单，但在处理空格不固定的输出（如 `ps` 或 `df` 命令）时非常难用。**建议直接使用 `awk`**。

| 命令 | 功能 | 常用选项 | 实战举例 (知识难点) |
| :--- | :--- | :--- | :--- |

| **tr** | 字符转换 | `-d` : 删除字符 | **修复Windows文件格式**<br>`cat win.txt \| tr -d '\r' > linux.txt` |

## 3. Vim 编辑器 (生存指南)

运维不仅要会改文件，还要改得快、改得准。

*   **核心模式**：
    *   `Esc`：万能键，迷路了就多按几次，回到普通模式。
    *   `i`：插入模式 (Insert)。
    *   `:`：命令模式 (保存/查找)。

*   **光标移动 (普通模式)**：
    *   `G`：文件末尾； `gg`：文件开头。
    *   `$`：行尾； `0`：行首。

*   **编辑操作 (普通模式)**：
    *   `dd`：剪切/删除当前行。 `5dd` 删除5行。
    *   `yy`：复制当前行。 `p`：在下方粘贴。
    *   `u`：撤销 (Undo)。 `Ctrl+r`：重做 (Redo)。

*   **块操作 (高阶技巧)**：
    *   **批量注释**：
        1.  `Ctrl + v` 进入可视块模式。
        2.  方向键选中多行的开头。
        3.  `Shift + i` (大写I) 进入插入模式。
        4.  输入 `#`。
        5.  连按两次 `Esc`，奇迹发生（多行都被注释了）。

## 4. 💡 知识难点与场景解析 (举例说明)

#### 难点1：为什么要用 `awk` 而不是 `cut`？
*   **场景**：使用 `df -h` 查看磁盘。
    ```text
    Filesystem      Size  Used Avail Use% Mounted on
    /dev/sda1        50G   20G   30G  40% /
    ```
*   **问题**：中间的空格数量是不固定的。
    *   如果你用 `cut -d " " -f 3`，大概率取到的是空值，因为 `cut` 认为两个空格中间有一个空字段。
    *   如果你用 `awk '{print $3}'`，`awk` 会自动忽略所有连续的空格，准确取到 `30G`。

#### 难点2：日志分析组合拳 (`sort | uniq -c | sort -nr`)
这是运维面试和实战中最常见的“连招”。
*   **场景**：Nginx 的 `access.log` 被攻击了，想找出哪个 IP 访问次数最多。
*   **命令**：
    ```bash
    awk '{print $1}' access.log | sort | uniq -c | sort -nr | head -n 10
    ```
*   **解析**：
    1.  `awk`：先把 IP 这一列单独拎出来。
    2.  `sort`：**必须先排序**，因为 `uniq` 只能去重相邻的行。
    3.  `uniq -c`：去重并计数（变为：`1024  192.168.1.1`）。
    4.  `sort -nr`：按计数（第一列）数值倒序排列，最大的在上面。
    5.  `head -n 10`：只看前10名“攻击者”。

## 3. 用户与权限管理

#### 1. 用户与组管理 (账号生命周期)

**重点强调**：
*   不要手动修改 `/etc/passwd` 文件。
*   创建用户时，务必确认是否需要创建家目录（`-m`）和指定 Shell（`-s`），否则用户登录后可能是个“残废”状态。

| 命令 | 功能 | 常用选项 | 实战举例 |
| :--- | :--- | :--- | :--- |
| **useradd** | 创建新用户 | `-m` : 创建家目录 (必须加)<br>`-s` : 指定Shell (如 `/bin/bash`)<br>`-g` : 指定组 | `useradd -m -s /bin/bash deploy` <br> *(创建一个标准的运维部署账号)* |
| **passwd** | 修改密码 | 无 (交互式) | `passwd deploy` <br> *(root可强行修改任何人密码)* |
| **userdel** | 删除用户 | `-r` : **连同家目录一起删除** (彻底清理) | `userdel -r old_user` |
| **usermod** | 修改用户信息 | `-aG` : 追加到新组 (不覆盖原组) | `usermod -aG root zhangsan` <br> *(把张三加入root组，赋予高权限)* |
| **groupadd** | 创建组 | 无 | `groupadd docker` |

#### 2. 权限控制 (chmod) —— 也就是“谁能做什么”

**核心口诀 (R=4, W=2, X=1)**：
*   **7** (4+2+1) = 读+写+执行
*   **6** (4+2) = 读+写
*   **5** (4+1) = 读+执行
*   **4** = 只读

**运维铁律**：永远不要给文件设置 `777` (任何人可写)，除非你想被黑客入侵。

| 命令 | 功能 | 常用格式 | 实战场景 (背下来) |
| :--- | :--- | :--- | :--- |
| **chmod** | 修改读写执行权限 | `chmod [数字] 文件`<br>`-R` : 递归修改 (含子目录) | **`chmod 600 id_rsa`** <br> *(SSH私钥必须是600，否则报错)*<br>**`chmod 755 script.sh`** <br> *(脚本标准权限：自己可写，别人可运行)*<br>**`chmod 644 nginx.conf`** <br> *(配置文件标准：自己可写，别人只能看)* |

#### 3. 归属权控制 (chown) —— 也就是“东西是谁的”

**重点强调**：`chwon` 是图中的拼写错误，正确是 **`chown`** (Change Owner)。
在部署 Web 服务（如 Nginx, Tomcat, MySQL）时，`chown` 比 `chmod` 用得更多。

| 命令 | 功能 | 常用选项 | 实战举例 |
| :--- | :--- | :--- | :--- |
| **chown** | 修改文件拥有者 | `-R` : 递归修改 (最常用)<br>格式: `用户:组` | `chown -R www:www /var/www/html` <br> *(把网站目录给www用户，否则Nginx没法写入日志或上传图片)* |

#### 4. 身份切换 (su 与 sudo)

**重点强调**：这是新手最容易混淆的地方。

| 命令 | 功能 | 区别与建议 | 实战举例 |
| :--- | :--- | :--- | :--- |
| **sudo** | 以管理员身份执行命令 | **推荐使用**。操作有记录，权限可控。 | `sudo systemctl restart nginx` |
| **su** | 切换用户 | **`su - 用户名`** (推荐)<br>**`su 用户名`** (不推荐) | **`su - prod`** <br> *(注意中间的减号 `-`，表示连同环境变量一起切换，否则不仅命令找不到，脚本也会报错)* |

---

### ⚠️ 运维避坑指南 (特别说明)

1.  **关于 `chmod 777`**：
    *   **现象**：程序报错 "Permission denied"。
    *   **新手做法**：`chmod -R 777 /app` (问题解决了，但安全漏洞打开了)。
    *   **正确做法**：先看文件属于谁？用 `chown` 把文件归属权给运行程序的用户；或者用 `chmod 755`。

2.  **关于 `root` 运行**：
    *   尽量避免直接用 `root` 账号运行业务程序（如 Tomcat、Node.js）。
    *   一旦程序有漏洞，黑客拿到的就是皇帝权限，系统直接报废。
    *   **做法**：创建专用的普通用户（如 `nginx`、`mysql`）来启动服务。

3.  **关于 `sudo` 授权**：
    *   如果你想让普通用户能用 sudo，不要改 `/etc/sudoers` 文件权限！
    *   **正确做法**：使用 `visudo` 命令来编辑，它会帮你检查语法错误。如果语法错了，你也退不出去了，系统可能会锁死。

4.  **SSH 密钥权限**：
    *   如果你发现配置了 SSH 免密登录却不生效，第一时间检查 `~/.ssh/` 目录权限必须是 `700`，`authorized_keys` 必须是 `600`。权限太开放，SSH 会拒绝登录。



在这个板块，我有两个特别的建议：
1.  **小心 `rm`**：这是唯一能让你瞬间“提桶跑路”的命令。
2.  **学会 `ln -s`**：软连接是版本发布和配置管理的神器。
3.  **用好 `rsync`**：它比 `cp` 更可靠，特别是传大文件时。

| **mkdir**| 创建目录 | **`-p` : 递归创建 (最常用)** | `mkdir -p /data/backup/mysql` <br> *(路径不存在也没事，一次性建好)* |
| **cp** | 复制文件/目录 | `-r` : 递归复制目录<br>**`-a` : 保留权限和时间(备份必用)** | `cp -a site.conf site.conf.bak` <br> *(改配置前先备份，用-a保留原文件属性)* |

#### 3. 高级路径操作 (Pushd/Popd)

这组命令适合在**Shell 脚本**中处理路径切换，或者手动操作时需要维护一个“目录栈”。

*   **pushd /path**：切换到目标目录，并将当前目录压入栈中。
*   **popd**：弹出栈顶目录，跳回刚才的位置。
*   **场景**：你需要去 `/var/log` 看一眼，然后再去 `/etc` 改个配置，最后还得回到 `/home` 继续工作。

#### 4. 软链接 (ln) —— 运维发布的核心技术

运维一定要分清**软链接 (Soft Link)** 和 硬链接。99% 的场景我们只用软链接。

*   **语法**：`ln -s [真实源文件] [快捷方式名]`
*   **实战场景**：
    1.  **版本发布**：
        *   真实目录：`/app/site_v1.0`, `/app/site_v1.1`
        *   软链接：`/app/site_current -> /app/site_v1.1`
        *   **回滚**：只需要修改软链接指向 v1.0 即可，瞬间完成，无需拷贝文件。
    2.  **Nginx 配置**：
        *   `sites-enabled` 里的文件通常是指向 `sites-available` 的软链接。
*   **举例**：
    ```bash
    ln -s /usr/local/python3/bin/python3 /usr/bin/python
    # (让系统默认python指向我们安装的新版本)
    ```

#### 5. 数据同步神器 (rsync)

比 `cp` 更强大，支持增量同步，断点续传。

| 命令 | 功能 | 常用选项 | 实战举例 |
| :--- | :--- | :--- | :--- |
| **rsync** | 远程/本地同步 | `-a` : 归档模式(保留所有属性)<br>`-v` : 显示过程<br>`-z` : 压缩传输 | `rsync -avz /data/www/ root@192.168.1.5:/backup/www/` <br> *(把本地网站目录同步到备份服务器)* |

> **Rsync 坑点提示**：
> 注意目录后面的斜杠 `/`。
> *   `src/` (带斜杠)：同步目录**里面的内容**。
> *   `src` (不带斜杠)：同步**目录本身**。

---

### ⚠️ 运维避坑指南

1.  **关于 `rm -rf`**：
    *   永远不要在心情不好或疲劳时操作该命令。
    *   **禁止使用**：`rm -rf /` (现在的系统大多有保护，但别试)。
    *   **高危动作**：`rm -rf ${VAR}/*`。如果变量 `$VAR` 为空，你就在删除根目录下的所有东西。脚本里必须判断变量是否为空。

2.  **关于 `ln -s`**：
    *   创建软链接时，**源文件必须写绝对路径**（如 `/home/data/file`），不要写相对路径（`../file`）。否则一旦软链接移动位置，链接就失效了。

3.  **关于 `cp` 备份**：
    *   备份配置文件时，习惯加上时间戳，例如：
        `cp nginx.conf nginx.conf.20231027.bak`
        这样即使一周改了三次，也能找回每一次的版本。

## 5. 磁盘管理命令 

#### 1. 空间查看 (先看懂情况)

运维最常遇到的报警：**"磁盘使用率超过 90%"**。

| 命令 | 功能 | 常用选项 | 实战举例 & 避坑 |
| :--- | :--- | :--- | :--- |
| **df** | 查看**磁盘分区**使用情况 | `-h` : 人类可读格式(G/M)<br>`-T` : 显示文件系统类型(xfs/ext4)<br>`-i` : 查看 Inode 使用率 | **`df -Th`** <br> *(最常用的巡检命令)*<br>*(坑：有时磁盘没满，但 `df -i` 满了，导致无法写入小文件)* |
| **du** | 查看**文件/目录**大小 | `-s` : 汇总显示(Summary)<br>`-h` : 人类可读<br>`--max-depth=1` : 只看一层 | **`du -sh *`** <br> *(在当前目录下，看哪个子目录占用最大，排查大文件必用)* |
| **lsblk**| 查看**磁盘物理结构** | `-f` : 显示文件系统信息 | `lsblk` <br> *(非常直观地看硬盘、分区、挂载点的树状结构，扩容前必看)* |
| **blkid**| 查看磁盘 UUID | 无 | `blkid` <br> *(写 `/etc/fstab` 自动挂载时，必须用 UUID，别用设备名)* |

> **🔥 经典面试题/故障场景**：
> **Q**: 为什么 `df -h` 显示磁盘满了，但用 `du -sh` 把所有文件加起来却没满？
> **A**: 因为有文件被删除了，但进程（如 Nginx/Java）还占用着句柄，空间未释放。
> **解法**: 用 `lsof | grep deleted` 找到进程，重启它或 `kill` 掉。

#### 4. LVM 逻辑卷管理 (难点 & 重点)

这是企业级运维必须掌握的。LVM 允许你**在线动态扩容**磁盘，而不需要停机。
图里只写了 `LVM`，实际操作涉及一系列命令。

**LVM 扩容三部曲 (背下来)**：
1.  **PV (物理卷)**: 也就是买回来的真实硬盘。
2.  **VG (卷组)**: 把硬盘融合成一个大存储池。
3.  **LV (逻辑卷)**: 从池子里切出来的分区（我们平时用的 `/data`）。

**常用命令链：**

| 阶段 | 命令 | 功能 | 实战场景 (假设新加硬盘 sdb) |
| :--- | :--- | :--- | :--- |
| **1.做PV** | `pvcreate` | 创建物理卷 | `pvcreate /dev/sdb` |
| **2.扩VG** | `vgextend` | 把新盘加入卷组 | `vgextend centos /dev/sdb` <br> *(把sdb扩容到名为centos的卷组里)* |
| **3.扩LV** | `lvextend` | 扩大逻辑卷空间 | `lvextend -l +100%FREE /dev/centos/root` <br> *(把卷组里剩下的空间全给root分区)* |
| **4.生效** | `xfs_growfs`<br>或 `resize2fs` | **刷新文件系统** (关键) | `xfs_growfs /` (针对xfs)<br>`resize2fs /dev/mapper/xxx` (针对ext4)<br>*|

### ⚠️ 运维避坑指南 (血泪经验)

1.  **格式化要三思**：
    *   敲 `mkfs` 之前，必须用 `lsblk` 或 `df` 确认好设备名！
    *   `/dev/sda` 通常是系统盘，**绝对不能格**。
    *   `/dev/sdb` 才是数据盘。

2.  **自动挂载陷阱**：
    *   修改 `/etc/fstab` 之前，先 `cp /etc/fstab /etc/fstab.bak`。
    *   写完后，**必须手动执行 `mount -a` 测试**。如果不报错，再重启。
    *   如果在 `fstab` 里写错了，重启后服务器会起不来（需要去机房接显示器或者通过云控制台修）。

3.  **LVM 扩容**：
    *   扩容是单向的（从小变大）比较安全。
    *   **缩容**（从大变小）非常危险，极易损坏数据，生产环境通常只扩不缩。

4.  **DD 命令**：
    *   `dd` 被戏称为 "Disk Destroyer"。
    *   `if` 和 `of` 写反了，数据就没了。一定要看清哪个是源(input)，哪个是目标(output)。

### ⚠️ 运维避坑与经验谈

1.  **关于 `ping` 不通**：
    *   Ping 不通不代表网络不通，可能是对方开启了**禁 ping** (防火墙拦截 ICMP 包)。
    *   **进阶做法**：用 `telnet` 或 `nc` 去测业务端口（如 80, 22）。如果 ping 不通但端口通，服务就是好的。

2.  **关于 `curl` 排错**：
    *   如果你访问外网慢，用 `curl -v www.baidu.com`。
    *   如果卡在 `Resolving...`，是 **DNS** 问题。
    *   如果卡在 `Connecting...`，是 **网络/防火墙** 问题。

3.  **关于 `localhost` vs `127.0.0.1` vs `0.0.0.0`**：
    *   `127.0.0.1`：只有本机能访问。
    *   `0.0.0.0`：**所有**网卡都能访问（对外提供服务必须监听这个）。
    *   如果你的服务监听在 `127.0.0.1:8080`，局域网别的机器是连不上你的，必须改成 `0.0.0.0:8080`。

4.  **抓包神器 tcpdump**：
    *   当开发甩锅说：“我请求发过去了，是你服务器没响应！”
    *   你直接在服务器抓包：`tcpdump -i eth0 port 8080`。
    *   如果**没抓到包** -> 网络中间链路问题（防火墙/云安全组），开发去查网络。
    *   如果**抓到了包但没回包** -> 也就是看到了 `SYN` 包没有 `ACK` -> 服务挂了或处理太慢，运维/开发查服务。

### ⚠️ 运维避坑与深度解析 

#### 1. 必须看懂的进程状态 (top 中的 S 列)

在 `top` 或 `ps` 命令中，有一列状态 (STAT/S)，必须看懂：

*   **R (Running)**: 正在跑。
*   **S (Sleeping)**: 睡眠中（大部分进程应该是这个状态）。
*   **D (Uninterruptible sleep) [危险]**: **不可中断睡眠**。通常是 **IO 卡死**（硬盘坏了或 NFS 挂了）。此时 `kill -9` 也杀不掉它，只能重启系统。
*   **Z (Zombie) [警惕]**: **僵尸进程**。进程运行完了，但父进程没给它“收尸”。僵尸进程不占 CPU/内存，但占进程号。如果有几万个僵尸进程，系统就无法创建新进程了。

#### 2. CPU 飙高排查流程 (标准动作)

1.  **`top`** -> 找到 CPU 占用最高的 PID (假设是 1001)。
2.  **`top -H -p 1001`** -> 查看该进程下哪个 **线程 (Thread)** 占用高。
3.  **`strace -p 1001`** (慎用) -> 跟踪系统调用，看它在干嘛（是在疯狂读写文件，还是在死循环）。

#### 3. 内存泄漏排查

*   如果在 `top` 里看到某进程 `RES` (物理内存) 一直涨不掉，多半是内存泄漏。

#### 4. 关于 Crontab 的坑

*   **环境变量问题**：Crontab 执行时不加载用户的 `.bash_profile`。
    *   *错误写法*：`java -jar xxx.jar` (找不到 java 命令)
    *   *正确写法*：`/usr/local/jdk/bin/java -jar xxx.jar` (必须用绝对路径！)
*   **输出重定向**：
    *   如果不加 `> /dev/null 2>&1`，Crontab 会把脚本输出通过邮件发给 root，久而久之 `/var/spool/mail` 会把磁盘撑爆。

## 8. 系统监控与性能分析

#### 1. 全局概览 

当你登录一台慢卡顿的服务器，第一件事就是敲这两个命令。

| 命令 | 场景 | 关键看哪里 |
| :--- | :--- | :--- |
| **top** | **系统综合状态** | **1. Load Average (平均负载)**: 右上角的三个数（1分钟/5分钟/15分钟）。如果数值超过了CPU核数，说明系统过载了。<br>**2. %CPU**: 也就是 `%wa` (IO wait)。如果这个高，说明CPU在等硬盘，瓶颈在磁盘IO。 |
| **htop** | **(推荐) 可视化Top** | 比 `top` 有颜色，支持鼠标点击，条形图一目了然。 |
| **uptime**| **只看负载** | 如果只想看系统运行了多久、负载多少，不想刷屏，就用这个。 |

#### 2. CPU 维度的分析

如果 `top` 显示 CPU 很高（us 或 sy 高）：

| 命令 | 功能 | 常用格式 | 实战解读 |
| :--- | :--- | :--- | :--- |
| **mpstat** | 查看**多核**CPU详情 | `mpstat -P ALL 1` | **场景**：总CPU占用不高，但程序很慢。<br>**查法**：用这个命令看是不是**某一颗核**被打满了（单线程程序的通病）。 |
| **pidstat**| 查**进程**的CPU | `pidstat -u 1` | 看具体是哪个进程在每秒钟吃掉多少 CPU。 |

#### 3. 内存维度的分析 (RAM)

如果程序报错 "Out of Memory" 或者系统变慢（开始用 Swap）：

| 命令 | 功能 | 常用格式 | 实战解读 |
| :--- | :--- | :--- | :--- |
| **free** | 查看内存使用量 | **`free -h`** | **重点看 `available`**：这是你真正还能用的内存。<br>**注意**：`buff/cache` 占用高是正常的（Linux 会把空闲内存拿来做文件缓存），不用惊慌，除非 `available` 也很低。 |
| **vmstat** | 虚拟内存统计 | **`vmstat 1`** | **(核心命令)** 每秒刷新一次。<br>**看 `si` 和 `so`**：如果这两个数非 0，说明系统在频繁使用 Swap 分区（硬盘当内存用），系统会卡顿，必须加内存了。 |

#### 4. 磁盘 I/O 维度的分析 (硬盘读写)

| 命令 | 功能 | 常用格式 | 实战解读 |

| **iotop** | 查**谁**在读写硬盘 | `iotop -o` | 类似于 top，但是按 IO 排序。瞬间抓出是谁在疯狂写日志或读数据库。 |

#### 5. 网络流量维度的分析

如果感觉网速慢，或者带宽被打满了。

| 命令 | 功能 | 常用格式 | 实战解读 |
| :--- | :--- | :--- | :--- |

| **iftop** | **(推荐) 流量监控** | `iftop` | **最好用的工具**。能实时显示**本机在和哪个IP进行流量传输**，且显示速度。谁在跑流量一目了然。 |

### 💡 运维排查思路 (打印这个贴在脑门上)

当有人喊“服务器卡了”，请按以下顺序操作：

1.  **先看负载**：敲 `top`。
    *   如果 **Load** 高，继续往下查。
    *   如果 **Load** 低，可能是网络卡或应用代码锁死。

2.  **看是缺什么**：在 `top` 界面看 `%CPU` 行：
    *   **`us` (User) 高** -> 程序自己在算东西（如加解密、压缩） -> 查代码逻辑。
    *   **`sy` (System) 高** -> 进程切换太频繁或驱动问题。
    *   **`wa` (Wait) 高** -> **硬盘慢！** -> 敲 `iostat -xz 1` 确认 -> 敲 `iotop` 抓元凶。
    *   **`id` (Idle) 高** -> CPU 没事干，那就是网络卡或数据库没返回。

3.  **看内存**：敲 `free -h`。
    *   如果 `available` 很小，且 `vmstat 1` 里的 `si/so` 狂跳 -> **内存不足**，导致系统在硬盘上反复摩擦（Swap），机器会巨卡。

### 总结：你的“精简工具箱”
如果你不想记那么多，只装这 4 个工具就够覆盖 90% 的场景：
1.  **`htop`** (看 CPU 和 内存)
2.  **`iotop`** (看 硬盘是谁在写)
3.  **`iftop`** (看 网络是谁在用)
4.  **`dstat`** (全能选手，一行显示 CPU/Mem/Disk/Net 状态)

### 💡 运维避坑指南

1.  **关于 `find` 的性能**：
    *   不要在生产环境的高峰期执行 `find / -name xxx`。
    *   这会遍历整个硬盘，导致磁盘 I/O 飙升，业务可能会卡顿。
    *   尽量缩小范围，比如 `find /var/log ...`。

2.  **关于 `date` 时间**：
    *   服务器时间对不上（比如差了8小时），会导致日志时间错乱，甚至导致鉴权失败（Token过期）。
    *   装机后第一件事：检查时区 (`timedatectl`) 和配置时间同步 (`chrony` 或 `ntp`).

3.  **关于 `history` 安全**：
    *   **千万不要**在命令行里直接带明文密码，比如 `mysql -u root -p123456`。
    *   因为 `history` 会把它记下来，谁登上来都能看到你的密码。

### 12. 现代运维补充包 

#### 1. 服务管理 (Systemd) —— 替代了旧的 `service` / `chkconfig`
现在的 Linux 发行版（CentOS 7+, Ubuntu 16+）基本都用 Systemd 管理服务。**不掌握这个，服务起不来你都不知道去哪看。**

| 命令 | 功能 | 常用动作 | 实战举例 |
| :--- | :--- | :--- | :--- |
| **systemctl** | 管理服务状态 | `status` : 看状态 (绿点是好，红点是挂)<br>`start/stop` : 启停<br>`restart` : 重启<br>`enable` : **开机自启** | **`systemctl status nginx`** <br> *(先看活没活)*<br>`systemctl enable --now nginx` <br> *(设为开机自启，并立刻启动)* |
| **journalctl**| **查看服务日志**<br>(Systemd 专属) | `-u` : 指定服务<br>`-f` : 实时滚动 (像 tail -f)<br>`-xe` : **看启动报错详情** | **`journalctl -u nginx -f`** <br> *(实时看 nginx 的控制台日志)*<br>**`journalctl -xe`** <br> *(服务启动失败时，系统提示你运行这个看详细报错)* |

#### 2. 软件安装 (包管理器)
手册里完全没提怎么装软件。

| 命令 | 适用系统 | 常用操作 | 实战举例 |
| :--- | :--- | :--- | :--- |
| **yum / dnf** | CentOS/RedHat | `install` : 安装<br>`remove` : 卸载<br>`update` : 更新 | `yum install -y vim telnet` <br> *(安装 vim 和 telnet，-y 表示全部选是)* |
| **apt / apt-get**| Ubuntu/Debian | `install` / `remove` | `apt update && apt install nginx` |
| **rpm** | 通用包管理 | `-ivh` : 安装本地包<br>`-qa` : 查询已安装 | `rpm -qa | grep mysql` <br> *(查查系统里有没有装过 mysql)* |

#### 3. 管道神队友 (xargs)
很多命令（如 `rm`, `kill`）不支持管道传参，必须用 `xargs` 桥接。它是**批量操作神器**。

| 命令 | 功能 | 实战场景 (背诵) |
| :--- | :--- | :--- |
| **xargs** | 把标准输入转为参数 | **场景1：批量删除**<br>`find ./ -name "*.log" | xargs rm -rf`<br>*(找到所有log文件，传给rm删掉)*<br><br>**场景2：批量杀进程**<br>`ps -ef | grep "python" | awk '{print $2}' | xargs kill -9`<br>*(找到PID，传给kill杀掉)* |

#### 4. JSON 处理神器 (jq)
现在的配置文件、API 返回结果、Docker 里的配置全是 JSON 格式。用 `grep` 和 `awk` 处理 JSON 很痛苦，**`jq`** 是必备的。

| 命令 | 功能 | 实战举例 |
| :--- | :--- | :--- |
| **jq** | 格式化/提取JSON | `cat config.json | jq .` <br> *(把压缩成一行的 JSON 漂亮地打印出来)*<br>`curl ... | jq '.data.ip'` <br> *(直接提取 JSON 里的 IP 字段)* |

#### 5. 终端复用 (tmux / screen)
**痛点**：你在跑一个耗时 3 小时的脚本，结果网断了，脚本也断了。
**解法**：用 `tmux`。即使断网，任务还在服务器后台跑，连上能接着看。

| 命令 | 功能 | 简单操作 |
| :--- | :--- | :--- |
| **tmux** | 终端复用器 | 1. 输入 `tmux` 进入新窗口。<br>2. 跑任务。<br>3. 关掉 SSH 终端回家。<br>4. 回家后再连上 SSH，输入 `tmux attach`，**画面完全恢复**。 |

#### 6. 安全与防火墙 (SELinux & Firewalld)
运维最大的“坑”：配置都对，权限都对，就是访问不了。通常是这两个东西在拦截。

| 命令 | 功能 | 实战举例 |
| :--- | :--- | :--- |
| **getenforce** | 查看 SELinux 状态 | `Enforcing` (开启拦截) / `Permissive` (只警告不拦截)<br>*(如果不通，先 `setenforce 0` 临时关掉试试)* |
| **firewall-cmd**| CentOS 7 防火墙 | `firewall-cmd --list-ports` <br> *(查看开了哪些端口)*<br>`firewall-cmd --add-port=80/tcp --permanent` <br> *(永久开启80端口，记得 reload)* |
