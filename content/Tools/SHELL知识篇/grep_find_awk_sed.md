### 一、 grep 命令速查表 (搜索文件内容)

**核心心法**：`grep` 不仅仅是查找，更是**过滤**。运维最常用的场景是**从海量日志中提取关键报错**。

#### 1. 常用参数 (运维必背)

| 参数 | 功能 | 助记 | 场景说明 |
| :--- | :--- | :--- | :--- |
| **`-i`** | **忽略大小写** | **i**gnore | 搜 `error` 时也能搜到 `ERROR` 或 `Error`。 |
| **`-v`** | **反向查找** (排除) | in**v**ert | **最重要！** 比如查日志排除掉 "Debug" 信息。 |
| **`-r`** | **递归查找** | **r**ecursive | 在整个目录及子目录的所有文件中搜索。 |
| **`-n`** | 显示行号 | **n**umber | 方便定位后用 vim `+行号` 跳转去修改。 |
| **`-l`** | 只显示文件名 | **l**ist | 只要文件名，不需要具体内容 (常配合管道用)。 |
| **`-E`** | 支持扩展正则 | **E**xtended | 允许使用 `|` (或) 等高级符号。 |
| **`-o`** | 只输出匹配部分 | **o**nly | **提取神器**。比如只把日志里的 IP 地址抠出来。 |

#### 2. 上下文查找 (查报错必备)
当日志出现 `Exception` 时，光看那一行没用，你得看**报错前后的堆栈信息**。

| 参数 | 功能 | 实战命令 |
| :--- | :--- | :--- |
| **`-A n`** | 显示匹配行及**后** n 行 | `grep -A 20 "Error" app.log` <br>*(After: 往后看20行堆栈)* |
| **`-B n`** | 显示匹配行及**前** n 行 | `grep -B 10 "Error" app.log` <br>*(Before: 往前看，是谁触发的报错)* |
| **`-C n`** | 显示匹配行及**前后** n 行 | `grep -C 5 "Error" app.log` <br>*(Context: 前后都看)* |

#### 3. 运维实战场景

*   **场景 1：在配置文件目录里，找谁配了 "192.168.1.1"**
    ```bash
    grep -r "192.168.1.1" /etc/nginx/
    ```
*   **场景 2：查日志，排除 "info" 和 "debug"，且忽略大小写，只看报错**
    ```bash
    # 使用 -E 配合 | 表示“或”，同时排除 info 和 debug
    grep -E -v -i "info|debug" app.log
    ```
*   **场景 3：统计有多少个 IP 访问了网站 (提取 + 排序 + 计数)**
    ```bash
    # -o 只输出匹配到的IP正则部分
    grep -o -E "([0-9]{1,3}\.){3}[0-9]{1,3}" access.log | sort | uniq -c | sort -nr | head
    ```
*   **场景 4：找 java 进程 (排除 grep 本身)**
    ```bash
    ps -ef | grep java | grep -v grep
    ```

### 二、 find 命令速查表 (搜索文件位置)

**核心心法**：`find` 是直接扫描磁盘。**生产环境严禁直接 `find /`**，这会导致磁盘 I/O 飙升，服务器卡死。务必指定目录！

#### 1. 常用参数 (按属性查找)

| 参数 | 功能 | 常用格式 | 场景说明 |
| :--- | :--- | :--- | :--- |
| **`-name`** | 按文件名 | `-name "*.log"` | 支持通配符 `*`。 |
| **`-type`** | 按类型 | **`-type f` (文件)**<br>`-type d` (目录) | 精准查找，避免把目录当文件处理。 |
| **`-size`** | 按大小 | **`+100M`** (大于)<br>`-10k` (小于) | **清理磁盘神器**。找出谁占用了空间。 |
| **`-mtime`**| 按修改时间 | **`+7` (7天前)**<br>`-1` (24小时内) | **日志轮转神器**。找出旧日志。 |
| **`-maxdepth`**| 限制搜索深度 | `-maxdepth 2` | 只搜 2 层目录，防止递归太深太慢。 |

#### 2. 动作参数 (找到后干什么)

| 参数 | 功能 | 语法格式 | 警告 |
| :--- | :--- | :--- | :--- |
| **`-delete`** | 直接删除 | `find ... -delete` | **极度危险**，建议先不加这个跑一遍确认结果。 |
| **`-exec`** | 执行命令 | `-exec 命令 {} \;` | `{} `代表找到的文件名，`\;` 是结束符。 |
| **`| xargs`**| **(推荐)** 管道传递 | `find ... | xargs 命令` | 比 `-exec` 效率更高，处理大量文件首选。 |

#### 3. 运维实战场景

*   **场景 1：找出 `/var/log` 下大于 1G 的大文件**
    ```bash
    find /var/log -type f -size +1G
    ```
*   **场景 2：自动清理 30 天前的备份文件 (配合 rm)**
    ```bash
    # 方法 A (find原生):
    find /data/backup -name "*.sql" -mtime +30 -delete
    
    # 方法 B (推荐，看着安全点):
    find /data/backup -name "*.sql" -mtime +30 | xargs rm -f
    ```
*   **场景 3：找出最近 24 小时内被修改过的配置文件**
    ```bash
    # 比如怀疑谁改了配置导致故障
    find /etc -name "*.conf" -mtime -1
    ```
*   **场景 4：批量修改文件权限 (把所有 sh 脚本加执行权限)**
    ```bash
    find /app/scripts -name "*.sh" -type f -exec chmod +x {} \;
    ```

### 三、 附录：简单的正则表达式 (grep 必备)

在 `grep` 中使用正则，能极大提升效率。

| 符号 | 含义 | 举例 |
| :--- | :--- | :--- |
| **`^`** | **行首** | `grep "^Error"` (找以 Error **开头**的行) |
| **`$`** | **行尾** | `grep "OK$"` (找以 OK **结尾**的行) |
| **`.`** | 任意单个字符 | `grep "t.st"` (test, tast 都能匹配) |
| **`*`** | 重复前一个字符 | `grep "a*"` |
| **`|`** | **或者 (需加 -E)** | `grep -E "error|warn"` (找 error 或者 warn) |

---

### ⚠️ 运维避坑指南 (血泪经验)

1.  **关于 `find` 的时间计算 (`-mtime`)**：
    *   **`+7`**：意思是 **7 天以前** (Old)。
    *   **`-7`**：意思是 **7 天以内** (New)。
    *   *记忆口诀：`+` 是时间增加（变老），`-` 是时间减少（变新）。*

2.  **关于 `find` 删除文件**：
    *   执行 `find ... -delete` 或 `| xargs rm -rf` 之前，**必须先执行一遍不带删除动作的命令**，确认列出来的文件列表真的是你想删的！
    *   *错误案例*：本想删日志，结果写错了路径，把数据库删了。

3.  **关于 `grep` 二进制文件**：
    *   如果 grep 提示 `Binary file matches`，说明你在搜一个二进制文件（如程序本身）。
    *   加上 **`-a`** 参数可以将二进制文件视为文本搜索：`grep -a "config" my_program`。

### 三、 awk 命令速查表 (数据提取与统计)

**核心心法**：awk 默认把每一行按**空格**或**Tab**切分成若干**列 (Field)**。
*   `$1` 是第 1 列，`$2` 是第 2 列...
*   `$0` 是整行内容。
*   `$NF` 是最后一列 (End of Field)。

#### 1. 基础语法

```bash
awk [选项] '条件 {动作}' 文件
```

| 常用选项 | 功能 | 场景 |
| :--- | :--- | :--- |
| **`-F`** | **指定分隔符** | 默认是空格。处理 `/etc/passwd` 这种用 `:` 分割的文件时必用。 |
| **`NR`** | 行号变量 | `NR==1` (第一行), `NR>1` (从第二行开始) |

#### 2. 运维实战场景

*   **场景 1：打印特定列 (最常用)**
    > `df -h` 输出乱？只看磁盘剩余空间。
    ```bash
    # 打印第1列(设备名)和第4列(剩余空间)
    df -h | awk '{print $1, $4}'
    ```

*   **场景 2：指定分隔符提取数据**
    > 提取系统所有用户名 (在 `/etc/passwd` 第1列，用 `:` 分割)。
    ```bash
    awk -F ":" '{print $1}' /etc/passwd
    ```

*   **场景 3：条件筛选 (像 SQL 一样查询)**
    > 找出 CPU 占用 (`$3`) 大于 50% 的进程。
    ```bash
    ps -aux | awk '$3 > 50 {print $2, $3, $11}'
    # 逻辑：如果第三列大于50，打印 PID, CPU, 进程名
    ```

*   **场景 4：取倒数某一列**
    > 日志最后一段通常是状态码或响应时间。
    ```bash
    # 打印日志的最后一列
    tail access.log | awk '{print $NF}'
    # 打印倒数第二列
    tail access.log | awk '{print $(NF-1)}'
    ```

*   **场景 5：统计与求和 (进阶)**
    > 统计 Nginx 日志中所有请求的总字节数 (假设字节数在第 10 列)。
    ```bash
    # BEGIN:开始前做啥; END:结束后做啥
    awk '{sum += $10} END {print sum}' access.log
    ```

### 四、 sed 命令速查表 (流式编辑与替换)

**核心心法**：`sed` 是按行处理的。它读取一行 -> 处理一行 -> 输出一行。
**警报**：`sed -i` 会直接修改原文件！操作前务必备份或去掉 `-i` 先预览。

#### 1. 基础语法

```bash
sed [选项] '[地址]命令' 文件
```

| 常用命令 | 功能 | 助记 |
| :--- | :--- | :--- |
| **`s`** | **替换** (Substitute) | 最常用的功能。 |
| **`d`** | **删除** (Delete) | 删除指定行。 |
| **`p`** | 打印 (Print) | 常配合 `-n` 只显示处理过的行。 |
| **`i` / `a`**| 插入/追加 | **i**nsert (当前行前), **a**ppend (当前行后)。 |

| 常用选项 | 功能 | 警告 |
| :--- | :--- | :--- |
| **`-i`** | **直接修改文件** | **危险！** 一旦执行无法撤销。建议 `cp file file.bak` 再搞。 |
| **`-n`** | 取消默认输出 | 默认 sed 会把原文件打印一遍，加 `-n` 配合 `p` 只看我们想看的。 |

#### 2. 运维实战场景

*   **场景 1：文本替换 (配置文件修改)**
    > 把 `config.php` 里的 `debug = true` 改成 `debug = false`。
    ```bash
    # s/旧/新/g (g表示全局替换，否则只替每行第一个)
    sed -i 's/debug = true/debug = false/g' config.php
    ```

*   **场景 2：删除特定行**
    > 删掉文件里的空行，或删掉包含 "error" 的行。
    ```bash
    # 删除空行 (^$ 代表空行正则)
    sed -i '/^$/d' file.txt
    
    # 删除包含 "error" 的行
    sed -i '/error/d' file.txt
    ```

*   **场景 3：打印文件的第 10 到 20 行**
    > 文件太大，cat 会刷屏，head/tail 算起来麻烦。
    ```bash
    sed -n '10,20p' big_log.txt
    ```

*   **场景 4：在特定行前后插入内容**
    > 在配置文件的第 5 行后面加上一行 `port=8080`。
    ```bash
    sed -i '5a port=8080' config.conf
    ```

*   **场景 5：高级替换 (使用变量)**
    > 在 Shell 脚本里，把变量 `$PORT` 的值写入配置文件。
    ```bash
    # 注意：必须用双引号 ""，单引号里变量不生效！
    PORT=9090
    sed -i "s/8080/$PORT/g" server.xml
    ```

### ⚠️ 运维避坑指南 (AWK & SED 篇)

1.  **关于 `awk` 的列对齐**：
    *   `ps` 或 `ls -l` 的输出看似是对齐的，其实中间空格数量不一致。`awk` 默认会自动处理多个连续空格为一个分隔符，非常智能，不需要手动处理。

2.  **关于 `sed -i` 的安全性**：
    *   **新手大忌**：直接对重要配置运行 `sed -i`。
    *   **正确姿势**：先运行 `sed 's/old/new/g' file` (不带 -i)，看着输出结果在屏幕上是对的，再按 `Up` 键加上 `-i` 执行。

3.  **关于 `sed` 分隔符**：
    *   如果你要替换的内容里包含斜杠 `/` (比如路径 `/var/www/html`)，用默认的 `s///` 会报错。
    *   **技巧**：sed 允许自定义分隔符。可以用 `#` 或 `@` 代替 `/`。
    *   例如：`sed -i 's#/var/www#/opt/www#g' config.conf` (清晰多了，不用疯狂转义)。

###  5、 运维实战·黄金组合拳 (建议背诵)

**场景 1：统计访问量最高的 IP (Web日志分析)**
> 逻辑：打印IP列 -> 排序 -> 去重并统计次数 -> 按次数倒序 -> 取前10
```bash
awk '{print $1}' access.log | sort | uniq -c | sort -nr | head -n 10
```

**场景 2：批量杀掉特定进程**
> 逻辑：列出进程 -> 过滤名字 -> 排除grep自己 -> 取进程ID -> 传参给kill
```bash
ps -ef | grep "nginx" | grep -v "grep" | awk '{print $2}' | xargs kill -9
```

**场景 3：查看并清理空行**
> 逻辑：正则匹配空行并删除
```bash
sed -i '/^$/d' filename.txt
```

**场景 4：查找最近报错的上下文**
> 逻辑：找到 Error，并把它的后 10 行也打出来，方便排查原因
```bash
grep -A 10 "Exception" catalina.out
```
