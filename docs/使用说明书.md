# 云海小鲸使用说明书

文档示例目录：`D:\Projects\personal-blog`，请替换成自己的本地克隆目录。发布分支：`master`。网站：<https://chrunge.github.io/>。

## 1. 日常更新

同步仓库 → 编辑 Markdown 和图片 → 检查改动 → Commit → Push → 等待 [Actions](https://github.com/Chrunge/Chrunge.github.io/actions) 成功 → 打开网站确认。

Commit 保存本地版本；Push 上传版本并触发网站发布。日常写作不要求安装 Ruby。

## 2. 内容放在哪里

| 内容 | 编辑位置 |
| --- | --- |
| 博客文章、随笔、阅读笔记 | `_posts/`，文件名为 `YYYY-MM-DD-slug.md` |
| 小说、课程或工具专题 | `_novels/分类/作品名/`，一份 `.md` 是一章 |
| 漫画与画集 | `_manga/`，在 YAML 的 `pages` 列表排列图片 |
| 图片 | `assets/images/`，可按作品建立子目录 |
| 栏目介绍与布局 | `pages/`，每个文件显式填写 `permalink` |

“作品”统一展示小说、专题和漫画。主导航第三项“周朝史”打开独立的[周朝时间线](https://chrunge.github.io/Zhou-Dynasty-Timeline/)。

文件使用 UTF-8，确认扩展名为 `.md`。网页网址由 `permalink` 或内容文件名决定，不使用电脑上的 `D:\…` 路径。发布后尽量保持作品目录和文件名稳定。

## 3. 添加博客文章

在 `_posts/` 新建 `2026-10-17-autumn-reading.md`：

```markdown
---
title: "秋日阅读小记"
date: "2026-10-17 09:00:00 +0800"
category: "阅读笔记"
tags: ["阅读笔记", "随笔"]
description: "记录这次阅读中留下的几句话和思考。"
excerpt: "记录这次阅读中留下的几句话和思考。"
original_filename: "2026-10-17-autumn-reading.md"
toc_levels: "h2,h3"
---

这里写开头。

## 为什么读这本书

段落之间空一行。

## 读后思考

这里继续写正文。
```

八个字段都需保留并修改为实际内容。`title` 是网页标题；`category` 是一项分类；`tags` 是非空列表；`description` 用于列表短摘要，`excerpt` 用于 RSS 等摘要；`original_filename` 记录源文件名；`toc_levels` 指定目录层级。

`date` 是实际发布时间，保留 `+0800` 时区。文件名的日期不会覆盖 YAML 日期。未来文章不会发布；时间到达后还需重新构建。示例地址为 `/blog/autumn-reading/`。

正文从 `##` 二级标题开始，网页会单独显示文章标题。草稿可添加 `published: false`；公开仓库里的源文件仍然公开，这个字段只控制网站显示。

### 图片

保存 `assets/images/uploads/autumn-lake.jpg`，在正文写：

```markdown
![秋天的湖面]({{ '/assets/images/uploads/autumn-lake.jpg' | relative_url }})
```

图片路径、大小写、扩展名必须与实际文件一致，并随文章一起提交。

## 4. 添加小说或专题章节

```text
_novels/
  小说/
    云海远行/
      01-出发.md
      02-风的来信.md
  Computer Science/
    6.S081/
      Lecture1 Introduction.md
```

每个直接包含 Markdown 的目录形成一个作品。章节沿用第三节的资料头，把标题、分类、摘要和原文件名改为本章内容；可追加 `order: 1` 指定章序。未指定时按文件名自然排序，`Lecture2` 在 `Lecture10` 前。

正文里的 `##` 划分本章小节，不会生成新章节。程序维护的 `layout`、`book_id`、`chapter_index`、`permalink` 保持原样；已有 `legacy_url` 用于旧地址跳转，也应保留。

章节可使用 `published: false` 保存草稿；默认不会进入书架、章数、上下章导航、标签或旧址跳转。未来日期的章节也需等待日期到达并重新构建。隐藏内容仍需完整元数据，公开仓库源码仍然可见。

已有标签可以手动修改，发布会保留。标签为空或缺失时，生成器按 `_data/tag_rules.yml` 的第一个前缀规则补充分类。课程使用统一课程标签，其他计算机笔记使用“编程语法篇”“工具篇”“原理篇”等分类。

## 5. 添加漫画或画集

准备 `assets/images/manga/my-series/cover.webp`、`001.webp`、`002.webp`。在 `_manga/` 新建 `my-series.md`，复制第三节的八个字段并改为本作品资料，再在同一个 YAML 头部追加：

```yaml
status: "已完结 · 2 页"
cover: /assets/images/manga/my-series/cover.webp
synopsis: "故事从一封飘来的信开始。"
pages:
  - /assets/images/manga/my-series/001.webp
  - /assets/images/manga/my-series/002.webp
```

`pages` 的顺序就是阅读顺序，不会扫描图片目录自动补页。新增图片时更新此列表和页数。封面需要在阅读页出现时，也要列入 `pages`。使用适合网页大小的 JPG、PNG、WebP 或 SVG，保留需要的透明背景。

AI 娘的网页图片位于 `assets/images/AI娘/`，资料在 `_manga/ai-girl.md`。本地 `_originals/` 保存的原始 PNG 不提交、不发布。第三方素材保留署名及授权说明，见[素材致谢与授权](../THIRD_PARTY_NOTICES.md)。

## 6. 手动提交

### GitHub Desktop

添加本地仓库 `D:\Projects\personal-blog`，确认分支为 `master`。写作前 Fetch／Pull；完成后在 Changes 检查文件，填写 Summary，Commit，再 Push。确认工作流 **Build and deploy Cloud Whale** 为绿色。

### GitHub 网页

在仓库选择 `master`，通过 Add file 新建或上传文件，或点击铅笔编辑。填写提交说明并 Commit changes。网页提交无需再 Push。图片多时推荐 Desktop，一次提交正文和图片。

### PowerShell

工作区干净时先同步：

```powershell
Set-Location 'D:\Projects\personal-blog'
git status
git pull --ff-only origin master
```

编辑后，用本次实际文件替换下列路径：

```powershell
git diff
git add -- _posts/2026-10-17-autumn-reading.md assets/images/uploads/autumn-lake.jpg
git diff --cached --stat
git diff --cached
git commit -m "新增：秋日阅读小记"
git push origin master
```

新文件在暂存前不会出现在 `git diff` 正文中，请在编辑器检查。首次使用可配置 `git config user.name`、`git config user.email`；推送使用 Desktop 或浏览器授权，不把令牌写入源码。发生冲突时比较两边内容，不直接强制推送。

## 7. 本地预览与检查

可选环境：Ruby 3.3、Bundler；Windows 原生扩展可能需要 RubyInstaller 开发工具。首次执行 `bundle install`，再运行：

```powershell
ruby scripts/prepare_library.rb
ruby scripts/check_content.rb
bundle exec jekyll serve --host 127.0.0.1
```

打开 <http://127.0.0.1:4000>，结束时按 Ctrl+C。新增、移除章节或修改日期、标签后，先重新运行作品准备脚本。

`_library/`、`redirects/`、`_data/library.json`、`_data/library_tree.json` 是被 Git 忽略的生成产物。首次克隆不会带有这些文件，运行准备脚本会创建；不要手工编辑、暂存或上传。`_site/`、`vendor/` 和 `.bundle/` 也不提交。归档与标签由 Jekyll 在构建时生成，无需单独准备索引文件。

页面检查需要 Python 3；阅读交互检查还需 Node 和浏览器依赖：

```powershell
ruby tests/content_test.rb
bundle exec ruby tests/discovery_check.rb
bundle exec jekyll build
python scripts/check_site.py _site
npm ci --prefix tests
node tests/node_modules/playwright/cli.js install chromium
node tests/reading.cjs _site
```

浏览器测试使用独立资料，截图写入 `tests/artifacts/`，不进入发布目录。不要直接双击源目录的 `index.html`，它需要 Jekyll 渲染。

## 8. 阅读操作

- 主题面板可选择九种渐变和夜间视图，选择保存在当前浏览器。
- 沉浸模式隐藏导航与装饰，按 Esc 或退出按钮恢复。
- 正文支持字号、代码语言角标、复制、目录和进度恢复。宽屏使用侧目录，手机及沉浸模式使用文内折叠目录。
- 阅读并滚动后，首页书架上方显示最近一项未读完内容。继续阅读会等待图片、字体和图表就绪或超时后恢复位置；清除记录会清除进度与最后章节，保留主题和字号。记录不跨设备同步。
- 小说章节、逐页漫画支持左右方向键；输入文字或打开图片弹窗时不会触发翻页。
- 图片和图表点击放大，用按钮或滚轮缩放，放大后拖动查看，Esc 关闭。图片加载失败可重新加载。

### Mermaid 图表

````markdown
```mermaid
flowchart LR
  A[Markdown 源文件] --> B[Jekyll 构建]
  B --> C[GitHub Pages]
```
````

图表自动适配日间／夜间主题，可放大和展开源码复制。含图表的页面从 jsDelivr 加载固定版本组件；网络或语法错误时保留源码和重试入口。图表只展示，不执行节点回调或打开节点链接。

## 9. 配置与排错

| 修改或问题 | 位置或检查项 |
| --- | --- |
| 站点元数据、简介、评论参数 | `_config.yml` |
| 页面显示的站名 | `_includes/header.html`、`_includes/footer.html`、`index.html`、`pages/about.md` |
| 主题名称／颜色 | `_data/themes.yml`／`assets/css/themes.css` |
| 友链 | `_data/links.yml` |
| 文章不显示 | 检查目录、日期、`published`、YAML 和本次部署 |
| 章节或标签不更新 | 重新运行准备脚本，检查工作流结果 |
| 图片破图 | 检查是否提交、路径、大小写、扩展名 |
| YAML 报错 | 空格缩进，文字用英文引号，保留八个字段与非空 `tags` |
| 页面仍显示旧版 | 确认对应提交部署成功，再强制刷新 |

Pages 来源使用 **GitHub Actions**。工作流在检查后部署，拉取请求只检查。未来时间到达、修改发布状态或需要重新生成时，可在 Actions 手动运行工作流。

Giscus 评论默认关闭；需要时启用 GitHub Discussions、安装 Giscus，并从 <https://giscus.app/> 获取 `_config.yml` 中的参数。

维护过程与问题排查记录统一见[维护历史](HISTORY.md)，源码职责与构建细节见[架构说明](architecture.md)。

## 公开内容与私人原稿

仓库是公开的，文章的 Markdown、图片、文件名、元数据和提交历史都可被访问。`published: false` 不能保护源码隐私。私人对话、涉及他人的经历、家庭健康和财务原稿，连同原始备份，都应保存在仓库之外；需要公开时，另写不含身份线索的版本。

发布前检查正文、合辑中的重复转述、摘要、图片内文字、截图和图片位置元数据。工作或学习笔记使用明确的示例地址与账号，不粘贴真实业务配置或访问口令。提交时逐文件确认，避免把私人备份一并选入。

提交邮箱按 [README 的设置说明](../README.md#提交邮箱与隐私) 使用 GitHub 提供的 noreply 地址。该设置只影响之后创建的提交；旧内容的历史清理需先保留私密备份，再另行安排。
