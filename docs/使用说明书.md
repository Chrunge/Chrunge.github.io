# 云海小鲸使用说明书

网站：<https://chrunge.github.io/>  
源码：<https://github.com/Chrunge/Chrunge.github.io>  
本地目录：`D:/Projects/个人Blog`  
发布分支：`master`

## 1. 日常更新流程

同步仓库 → 添加或修改内容 → 检查改动 → Commit 提交 → Push 推送 → 等待 Actions 成功 → 打开网站确认。

**Commit** 将修改保存为本地版本；**Push** 把版本上传到 GitHub，随后网站自动构建与发布。仅在本地提交，网站不会更新。

建议使用 GitHub Desktop。日常写作不必安装 Ruby，也不需要手工上传生成的网页。

## 2. 目录与网站栏目

| 网站栏目 | 内容来源 | 如何更新 |
| --- | --- | --- |
| 首页 | 最近三篇博客文章、作品入口 | 列表自动更新 |
| 博客 `/blog/` | `_posts/` | 新建带日期的 Markdown 文件 |
| 小说 `/novels/` | `_novels/分类/作品名/` | 每个直接包含章节的目录是一部作品，一份 Markdown 是一章 |
| 漫画 `/manga/` | `_manga/` 与图片 | 修改资料和 `pages` 图片列表 |
| 归档 `/archive/` | 博客文章的日期 | 按年份自动生成 |
| 标签 `/tags/` | 文章、章节、画集的 `tags` | 修改内容头部的标签 |
| 关于 `/about/` | `about.md` | 直接编辑 |

专业知识沿用 `Computer Science`、`Computer Tools`、`Economics` 等目录，收在小说与专题书架中。希望进入博客列表的随笔放在 `_posts/`。

图片统一放入 `assets/images/`，可按作品建立子目录。文件名建议用小写英文、数字和连字符；显示标题和目录可以用中文。文件保存为 UTF-8，并确认扩展名是 `.md`，不是 `.md.txt`。

以下文件由程序维护，**不要直接修改**：

- `_library/`：作品详情入口。
- `_data/library.json`、`_data/library_tree.json`：作品、章序与目录分类。
- `_data/discovery.json`：归档和标签索引。
- `redirects/`：旧文章网址到新章节的跳转页。

## 3. 添加博客文章

在 `_posts/` 新建 `2026-10-17-autumn-reading.md`，复制并修改：

```markdown
---
title: "秋日阅读小记"
date: "2026-10-17 09:00:00 +0800"
category: "阅读笔记"
tags: ["阅读笔记", "随笔"]
description: "记录这次阅读中留下的几句话和思考。"
excerpt: "记录这次阅读中留下的几句话和思考。"
original_filename: "2026-10-17-autumn-reading.md"
toc_levels: "h2,h3"
---

这里写开头。

## 为什么读这本书

这里写正文。段落之间空一行。

## 读后思考

这里继续写正文。
```

`---` 包住 YAML 资料，不要在第一行之前加正文。网页会自动显示 `title`，正文从 `##` 二级标题开始。

| 字段 | 用途 |
| --- | --- |
| `title` | 显示标题 |
| `date` | 发布时间，建议与文件名日期一致，保留 `+0800` 时区 |
| `category` | 一项分类名称 |
| `tags` | 非空标签列表，决定标签页归类 |
| `description` | 列表短摘要，建议一两句话 |
| `excerpt` | RSS 等位置使用的短摘要 |
| `original_filename` | 原始文件名；手工新建时填写当前文件名 |
| `toc_levels` | 正文目录显示的标题层级；默认写 `h2,h3` |

这篇文章的网址为 `https://chrunge.github.io/blog/autumn-reading/`。文件名日期后的部分决定默认网址；发布后尽量不要改名。

未来时间的博客文章默认不显示，日期到达后还需要触发一次构建。旧文章可以在 YAML 中保留准确的原日期；文件创建、修改时间不一定等于首次写作时间。

### 插入图片

先保存 `assets/images/uploads/autumn-lake.jpg`，再写：

```markdown
![秋天的湖面]({{ '/assets/images/uploads/autumn-lake.jpg' | relative_url }})
```

图片必须一起提交，路径大小写应与文件一致。不要使用 `D:\照片\图片.jpg` 这样的电脑路径。

## 4. 添加小说或专业知识章节

按目录组织作品：

```text
_novels/
  Computer Science/
    6.S081/
      Lecture1 Introduction.md
      Lecture3 OS Organization and System Calls.md
  小说/
    云海远行/
      01-出发.md
      02-风的来信.md
```

每个直接包含 Markdown 的目录会生成一个作品入口；更深的子目录继续形成分类。章节模板：

```markdown
---
title: "第一章：出发"
date: "2026-10-17 09:00:00 +0800"
category: "小说 / 云海远行"
tags: ["小说", "云海远行"]
description: "小鲸启程，寻找云海中的第一封信。"
excerpt: "小鲸启程，寻找云海中的第一封信。"
original_filename: "01-出发.md"
toc_levels: "h2,h3"
order: 1
---

## 晨光

这里写本章正文。
```

`order` 可选，用于显式指定章序。不填写时按文件名自然排序，例如 `Lecture2` 在 `Lecture10` 前。小说建议使用 `01-`、`02-` 编号。

新增章节只需放入对应目录，提交并推送。发布流程会生成作品详情、章节目录、上下章链接和继续阅读入口。程序生成的 `layout`、`book_id`、`chapter_index`、`permalink` 保持原样即可。

目录名或文件名变化会改变作品或章节网址。已有 `legacy_url` 用于维护旧链接，请保留。作品移除后还应检查对应跳转页，避免留下指向已删除页面的链接。

## 5. 添加漫画或画集

准备图片：

```text
assets/images/manga/cloud-journey/ch01/
  cover.jpg
  001.jpg
  002.jpg
```

在 `_manga/` 新建 `cloud-journey-ch01.md`：

```markdown
---
title: "云海远行 · 第一话"
date: "2026-10-17 09:00:00 +0800"
category: "漫画"
tags: ["漫画", "云海远行"]
description: "故事从一封飘来的信开始。"
excerpt: "故事从一封飘来的信开始。"
original_filename: "cloud-journey-ch01.md"
toc_levels: "h2,h3"
status: "已完结 · 2 页"
cover: /assets/images/manga/cloud-journey/ch01/cover.jpg
synopsis: "故事从一封飘来的信开始。"
pages:
  - /assets/images/manga/cloud-journey/ch01/001.jpg
  - /assets/images/manga/cloud-journey/ch01/002.jpg
---

这里可写创作说明，也可留空。
```

`pages` 的排列就是阅读顺序，程序不会扫描图片目录自动补页。新增一页时，要同时上传图片、增加 `pages` 项并更新 `status` 页数。封面要在阅读页出现，也需列入 `pages`。

每话可建一个文件，成为一个独立作品。支持连续浏览和逐页看图。建议使用压缩后的 JPG、PNG 或 WebP；透明图使用 PNG、WebP 或 SVG。单文件应远小于 GitHub 的 100 MiB 限制。

## 6. 使用 GitHub Desktop 提交（推荐）

首次使用：登录有仓库写权限的 GitHub 账号，选择 **File → Add local repository**，添加 `D:/Projects/个人Blog`，确认当前分支为 `master`。

每次更新：

1. 写作前点击 **Fetch origin**；出现 **Pull origin** 时同步远程修改。
2. 编辑内容、放好图片，保存文件。
3. 回到 **Changes** 查看改动，确认文件与正文符合预期。
4. 在 **Summary** 填写说明，例如“新增：云海远行第二章”。
5. 点击 **Commit to master**，再点击 **Push origin**。
6. 在 [Actions](https://github.com/Chrunge/Chrunge.github.io/actions) 确认本次部署成功。

不需要手工编辑书架和标签索引；发布流程会重新生成。若本地运行过生成脚本，相关生成文件也可随本次内容一起提交。

## 7. 使用 GitHub 网页提交

1. 打开仓库，确认分支是 `master`。
2. 新建文件使用 **Add file → Create new file**，输入完整路径，如 `_posts/2026-10-17-autumn-reading.md`。
3. 粘贴并修改模板；已有文件点击铅笔图标编辑。
4. 点击 **Commit changes**，填写说明并提交到 `master`。
5. 图片通过 **Add file → Upload files** 上传到对应目录。

网页提交直接写入远程，无需再 Push。图片较多时更适合 Desktop，可把正文与图片一次提交，避免上传过程中短暂缺图。网页 Markdown 预览与最终网站排版可能不同。

## 8. 使用 PowerShell 提交

先进入正式目录，确认状态。工作区干净时同步：

```powershell
Set-Location 'D:/Projects/个人Blog'
git status
git pull --ff-only origin master
```

完成编辑后，替换为这次实际修改的路径：

```powershell
git diff
git add -- _posts/2026-10-17-autumn-reading.md assets/images/uploads/autumn-lake.jpg
git diff --cached --stat
git diff --cached
git commit -m "新增：秋日阅读小记"
git push origin master
```

新文件在 `git add` 前不会出现在 `git diff` 正文中，请在编辑器中检查。小说章节和漫画同样添加对应 Markdown 及图片即可。

首次提交若提示作者未设置，在当前仓库设置一次：

```powershell
git config user.name "你的 GitHub 用户名"
git config user.email "你的 GitHub 提交邮箱"
```

可在 GitHub **Settings → Emails** 获取提交隐私邮箱。推送需要 GitHub 登录；浏览器授权或 Desktop 登录后再试，不要把密码或令牌写入源码。

若提示远程有新提交或发生冲突，先保存并比较两边改动。不要直接强制推送。

## 9. 本地预览与检查（可选）

正式发布依赖由 GitHub Actions 安装；仅写作和推送不要求本机预览环境。

本地预览需要 Ruby 3.3、Bundler。Windows 安装原生扩展时可能需要 RubyInstaller 开发工具。在项目根目录首次执行 `bundle install`，之后：

```powershell
ruby scripts/prepare_library.rb
ruby scripts/prepare_indexes.rb
ruby scripts/check_content.rb
bundle exec jekyll serve --host 127.0.0.1
```

打开 <http://127.0.0.1:4000>，结束时按 `Ctrl+C`。新增、删除章节或修改日期、标签后，先重新执行两个生成脚本，再刷新预览。

完整页面检查需要 Python 3：

```powershell
bundle exec jekyll build
python scripts/check_site.py _site
```

生成脚本会更新索引、作品入口、章节资料与跳转页。需要把本地生成结果也存入仓库时，一并检查并暂存实际变化的 `_novels/`、`_library/`、`_data/library.json`、`_data/library_tree.json`、`_data/discovery.json`、`redirects/`。

`_site/` 是可重新构建的网页输出，不提交。不要双击源目录的 `index.html`，它必须先经过 Jekyll 渲染。

## 10. 确认发布结果

打开 [GitHub Actions](https://github.com/Chrunge/Chrunge.github.io/actions)，找到与本次提交对应的 **Build and deploy Cloud Whale**：

- 排队、运行中：等待完成。
- 绿色成功：检查线上文章、图片和目录。
- 红色失败：打开失败步骤查看日志，修复后重新提交。

工作流会生成书架和索引、检查 YAML 与脚本、验证模拟子路径和正式站点的页面链接，最后部署。页面仍显示旧内容时，确认最新提交是否部署成功，再强制刷新浏览器。

仓库 **Settings → Pages → Build and deployment → Source** 应选择 **GitHub Actions**，使用项目自带的发布流程。

## 11. 常见问题

| 问题 | 检查方法 |
| --- | --- |
| 文章不显示 | 文件是否在 `_posts/`、文件名是否带日期、资料头是否完整、日期是否在未来、部署是否成功 |
| 小说没有新章节 | 文件是否在正确的作品目录，生成脚本与部署是否通过；`##` 只划分本章小节，不创建新章 |
| 漫画页数没增加 | 图片是否上传、`pages` 是否增加路径、顺序是否正确 |
| 图片破图 | 检查路径、大小写、扩展名以及图片是否提交 |
| YAML 错误 | 缩进用空格；标题等文字用英文引号；不要用 Tab |
| 检查提示缺字段 | 补齐模板中的八个公共字段，`tags` 使用非空列表 |
| 索引或目录不更新 | 本地重新运行两个生成脚本；线上查看最新工作流是否通过 |
| Git 看不到修改 | 确认编辑的是正式目录，文件已保存 |
| 章节正文里有“配图待补” | 原笔记没有对应图片；补图后替换提示文字并提交图片 |

## 12. 阅读设置与维护

右上角「主题」可选择九种渐变及夜间视图；沉浸模式隐藏导航与装饰，按 Esc 或退出按钮恢复。正文支持字号、目录、代码复制和阅读位置恢复；作品详情支持继续阅读。记录保存在当前浏览器，不会跨设备同步。

日常写作只需改内容和图片。站点名称、简介见 `_config.yml`；友链见 `_data/links.yml`；颜色见 `assets/css/themes.css`；首屏与导航样式见 `assets/css/refresh.css`。

评论默认关闭。若需要 Giscus，先为仓库启用 Discussions 并安装 Giscus，再从 <https://giscus.app/> 获取参数，填写 `_config.yml` 的 `comments` 配置。该功能需要额外配置才能使用。

仓库公开，提交的源码也公开。`published: false` 可以让文章不出现在网站中，但不会隐藏 GitHub 源文件。撤下公开内容可删除对应源文件并提交；历史版本仍可在 Git 中找到。

本说明和架构文档位于 `docs/`，不出现在网站导航中，可在本地或 GitHub 仓库阅读。


### 计算机标签与目录折叠

计算机课程保留统一课程标签，如 `CS61A`、`CS61B`、`CS61C`、`6.S081`、`CS144`、`CS162`、`15-445`。其他计算机内容按“编程语法篇”“工具篇”“原理篇”归类，经济学内容使用“经济学”。规则见 `_data/tag_rules.yml`，按从上到下第一个匹配的目录或文件前缀生效；发布时会同步到章节头部，避免再次产生大量细碎标签。个人文章与画集的标签仍由作者填写。小说页及旧书架入口的全部目录默认折叠，点击分类标题展开。

### AI 娘图片与授权

`assets/images/AI娘/` 中的 WebP 文件用于网页展示，保留原图尺寸；`_originals/` 保存本地原始 PNG，不提交也不参与 Jekyll 发布。新增原图后需要自行生成网页版本并更新 `_manga/ai-girl.md` 的 `pages`，不会自动扫描目录。致谢展示组件见 `_includes/ai-girl-credits.html`，授权范围见仓库根目录 `THIRD_PARTY_NOTICES.md`。使用第三方角色素材时保留署名与协议说明。
